# Что выложено в прод и когда

Одно место на весь проект. До 06.08 такого места не было: состояние прода
выводилось из коммитов и из памяти сессии — то есть из источников, которые
про прод не знают ничего. Коммит доказывает, что код написан, и не
доказывает, что он выложен; между этими двумя вещами у нас уже жила
разница в двое суток.

**Правило: выложил — дописал строку сюда, в тот же заход.** Строка
называет дату по UTC, что именно выложено и **чем это проверено на самом
проде**, а не «я помню, что деплоил».

Проверять состояние прода — не читать эту страницу, а снимать заново
(правило I6, часть 3: запись, названная по живым данным, обязана называть,
чем её снять). Команды ниже только читают.

```bash
# функции: имя и время последней выкладки каждой
gcloud functions list --project=mugam-club --format="value(name,updateTime)" | sort -k2

# переменные окружения конкретной функции
gcloud functions describe <имя> --project=mugam-club --region=europe-west3 \
  --format="value(serviceConfig.environmentVariables)"

# какой набор правил сейчас боевой (firestore и storage)
TOKEN=$(gcloud auth print-access-token)
curl -s -H "Authorization: Bearer $TOKEN" -H "X-Goog-User-Project: mugam-club" \
  "https://firebaserules.googleapis.com/v1/projects/mugam-club/releases"

# сам текст боевых правил — по id набора из ответа выше, дальше diff с файлом
curl -s -H "Authorization: Bearer $TOKEN" -H "X-Goog-User-Project: mugam-club" \
  "https://firebaserules.googleapis.com/v1/projects/mugam-club/rulesets/<id>"

# индексы
gcloud firestore indexes composite list --project=mugam-club
```

> **Ловушка REST-запроса к правилам:** без заголовка `X-Goog-User-Project`
> он отвечает `403 SERVICE_DISABLED` — «API требует quota project». Это
> сообщение читается как «доступа нет» и уводит к выводу, что боевые
> правила посмотреть нельзя. Их посмотреть можно; не хватало заголовка.
> Класс «утверждение об инструменте, не проверенное на инструменте»
> (конспект, раздел 5б).

## Снято с прода 06.08 (все времена — UTC)

### Правила Firestore — ОТСТАЮТ ОТ РЕПОЗИТОРИЯ

| | |
|---|---|
| боевой набор | `e5d7804f-c24e-416b-b08c-ab6658fc5860` |
| выложен | **03.08, 21:56** |
| размер | 826 строк против 972 в `firestore.rules`; расхождение — 162 строки |

Чего в проде нет:

- `clearsCancelFields`, `withdrawsCancelRequest`, `declinesCancelRequest` —
  вся серверная половина работы №6 (`7bd98dd`, 04.08);
- `namesOnlySelf` — защита трёх полей «кто это сделал» (N37, `1dc783b`,
  04.08);
- условия `status != 'cancelled'` и `stampsSelf()` в `confirmsCancel` —
  **щель N36 в проде открыта дословно**, проверено чтением боевого текста,
  а не по записи в реестре.

**Следствие, которое надо знать до прогона на трубках:** в проде
`requestsCancel()` разрешает ровно два ключа (`cancelRequestedBy`,
`cancelRequestedAt`), а клиент всеми четырьмя ходами пишет вдобавок
`lastActionBy` и `lastActionType` (`firestore_service.dart`). Значит
сегодня **все четыре хода отмены получают отказ по правам** — не половина
работы №6, а вся она. UI и триггер уведомлений при этом уже в проде (см.
ниже), то есть проверять отмену на устройствах до выкладки правил
бессмысленно: она не запишется.

| Что | Когда |
|---|---|
| общий деплой всех функций | **03.08, 18:38–22:09** (несколько заходов подряд: `remindUpcomingEventsHourly` 19:19, `onPersonalEventCreated` 20:00, `onJobOfferRoundChanged` 21:03, `onChatUpdated` 22:09) |
| `onPersonalEventUpdated` — **переразвёрнута отдельно** | **05.08, 04:50** |

Что вошло в отдельную выкладку `onPersonalEventUpdated` 05.08:

- `clearReadMark` — снятие отметки прочтения у второй стороны при правке
  мероприятия (половина починки N40);
- вместе с ней — **весь `eventNotifications.ts` на тот момент, включая
  триггер уведомлений об отмене** (`d45b773`, 04.08 18:11 UTC): четыре
  хода, четыре адресата, признак нового запроса по сдвигу
  `cancelRequestedAt`. Он живёт внутри `onPersonalEventUpdated`
  (`planUpdatePushes`), отдельной функцией не является.

> **Как это установлено и чего эта запись НЕ доказывает.** Время выкладки
> (05.08 04:50) позже коммита `6b6db2d` (05.08 04:38) и много позже
> `d45b773` — значит выложенный бандл собран из дерева, где триггер уже
> был. Это **вывод из времён, а не сверка исходников**: содержимое бандла
> напрямую не читалось. Сверка станет бесплатной на первом же прогоне
> отмены — но только после выкладки правил, иначе ход не запишется вовсе
> и молчание уведомления не будет значить ничего (I9: проверка, которая не
> может провалиться, ничего не доказывает).

Переменные окружения (сняты с `sweepDeadPushTokensDaily`, общие для
деплоя): `PUSH_TOKEN_SWEEP_DELETE=true`, `ORPHAN_SWEEP_DELETE=true` —
удаление включено у обоих сборщиков.
