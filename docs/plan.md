# ПОЛНЫЙ ПЛАН — mugam-flutter

## Принципы, которым подчинено всё

Одно касание. Музыкант не сидит в приложении — он за рулём, на сцене,
между делом. Если ради ответа надо зайти, найти и открыть — люди вернутся
к голосовым в WhatsApp.

Помнит, но не судит. Никаких рейтингов, счётчиков отказов, репутации.
Индустрия маленькая, досье никто не простит.

Много входов — одна точка вызова. Каждый раз, когда путей к операции
несколько, а код написан отдельно для каждого, один из них молча делает
не то. Так были N35, N40, `leaveGroup`/`removeGroupMember`.

## Часть 1. Панель вкладок

Из десяти работают пять: Klub, Kalendar, Axtar, Mesaj, Profil. Пять —
заглушки: Elanlar, Sifariş, Bazar, Hekayə, Video.

В панели остаются пять рабочих плюс шестая — Tezliklə, внутри список пяти
будущих экранов с одной строкой про каждый.

Заглушки не удаляются из кода — экраны и маршруты на месте. Готов
Elanlar — переезжает в панель.

Защита от забывания — строка в реестре с адресом работы, не комментарий.
Комментарий защищает строку, а не класс.

Панель перестаёт листаться вбок.

## Часть 2. Kalendar

Первая вкладка. Переключатель `Gün | Ay` внутри.

Gün — сегодня и завтра: что, где, во сколько, с кем. Ay — сетка месяца,
чтобы ответить на звонок «свободен 9-го?».

Один календарь в двух масштабах, не две вкладки.

**Прыжок по дате — сеткой, а не набором числа.** Случай, ради которого
он нужен: человеку звонят и спрашивают «свободен 9-го?», он отвечает не
отрывая телефон от уха. Одной рукой, не глядя.

**Сетка месяца И ЕСТЬ клавиатура** — цифры крупные, стоят на своих
местах, и на каждой уже нарисовано число мероприятий. Значит:

| Касание | Что видно |
|---|---|
| 1. `Ay` | сетка месяца. **Ответ уже здесь**: на 9-м есть кружок или нет |
| 2. по 9-му | под сеткой — что именно в этот день |

**Одно касание на «да/нет», два на «что именно».** Ни поле, ни колесо так
не умеют: клавиатура закрывает пол-экрана и требует точности, колесо
крутится вслепую.

**Решающий довод — сетка остаётся на экране.** В разговоре спрашивают про
несколько дат подряд; «а 10-го?» — это ещё одно касание, а не новый
заход. Прежнее поведение (нажатие уводило на закладку «Tədbirlər») ломало
ровно это.

**Далёкая дата — списком месяцев** по нажатию на заголовок: двенадцать
вперёд. Касания честно: **три внутри «Ay»** (заголовок → месяц → день) и
**четыре, если начинать с «Gün»** — первое уходит на переключатель.

**От набора числа с клавиатуры отказались совсем**, не вторым путём.
Довод: второй путь к той же операции — это то самое место, где правило
потом оказывается применено к одному из двух.

## Часть 3. Стартовый экран

Первый запуск после установки → Klub, со строкой «впишите свои даты» и
кнопкой в Kalendar. Один раз, потом навсегда исчезает.

Все последующие → Kalendar, вид Gün.

По уведомлению → куда ведёт уведомление, без мелькания другого экрана.

В профиле: «Tətbiq açılır…» — Kalendar или Klub. По умолчанию Kalendar.

Никакого «умного» выбора. Приложение, открывающееся по-разному,
ощущается сломанным.

## Часть 4. Точки на вкладках

Вкладка, которая не открывается сама, уходит из головы. Значок — защита от
этого.

**Значки разные, и это решение, а не недосмотр — уточнено 07.08.**
Исходная редакция требовала тихую точку на обеих вкладках, «не число».
На «Mesaj» сделано числом, и число там правильнее: человек хочет знать,
**сколько разговоров ждёт**, а не «что-то есть». Стоит с 07.08 —
`custom_tab_bar.dart`, счёт ЧАТОВ, не сообщений, «9+» дальше девяти.

**Точка остаётся для «Klub»** — там источника пока нет вовсе. И заводить
её раньше источника нельзя: получится N57 наизнанку — там было поведение
без наблюдаемости, здесь была бы наблюдаемость без поведения.

> **Открытый вопрос, без которого «Klub» не делается: что в «Klub»
> считается новым.** Пока на него нет ответа, значок стал бы правилом без
> источника.

Заглянул — ушло. Ни точка, ни число не красные.

## Часть 5. Предложение работы: одна точка вызова

Предложить можно откуда угодно — из чата, из карточки музыканта, из дня в
календаре, с главного экрана.

Код один. Входы только заполняют, что знают: из чата известен человек, из
дня известна дата, с главного — ничего.

Защита: тест по исходникам — никто в обход не пишет предложение напрямую.
Новый вход не сможет «забыть» проверку.

## Часть 6. Своя группа — шаблон, не сторона договора

Работодатель договорился с тобой. Договор один, стороны две. Твоя группа
к нему отношения не имеет.

На мероприятии кнопка «Öz adamlarımı çağır» — детали уже заполнены.
Выбрал людей, отправил. Каждый получает своё предложение от тебя.

Кто-то занят — сам отказывается, ищешь замену. Никого не записывают без
спроса.

Состав сохраняется шаблоном: собрал раз — дальше вызываешь одним ходом.

«Təkrar et» — тот же состав, новая дата. Тот же механизм, только шаблон
берётся из прошлого вечера.

Работодатель видит, что придёшь со своими. Показывать ли состав — твоё
решение.

## Часть 7. Уход из мероприятия

Кнопка «Məni azad et» плюс место сказать словами или голосом. Подсказки
есть, выбирать не обязательно.

Инициатор отвечает: отпускаю / жду замену / не отпускаю. Пока не
ответил — человек ещё в мероприятии.

Обещал замену — приложение помогает отправить предложение другому.

Письмо видят оба. У обоих на странице отменённых договоров, заголовок
«отправлено → инициатору (имя)». Сразу падает в чат системной записью.
Кнопка «ответить» ведёт в чат.

Редактировать нельзя. Удалить может только автор и только после даты
мероприятия — у обоих сразу, письмо одно.

Договор при уходе не отменяется молча. Переходит в «сторона вышла,
договор под вопросом».

Исходы: договорились — инициатор возвращает, вышедший подтверждает сам,
договор оживает. Не договорились — инициатор подтверждает расторжение.
Инициатор молчит — дата прошла, договор закрывается автоматически.

Вышедший остаётся стороной, пока договор жив. Повторный выход не
ограничен, все причины сохраняются списком.

## Часть 8. Отмена мероприятия

Одна кнопка «Tədbir ləğv edildi» плюс причина голосом или текстом.
Уведомление всем сразу, никому не звонить отдельно.

Сейчас это удаление — документ исчезает, следа нет. Станет отменой со
статусом.

Отдельно: `deletePersonalEvent` в приложении не вызывается ниоткуда —
удаление никогда не существовало как поступок, только замаскированным под
замену (N41). Этот метод и станет основой.

## Часть 9. Приватность по выбору музыканта

Календарь: показывать занятость или нет. По умолчанию закрыто.

Кто зовёт — чужой календарь не видит. Тот, кого зовут, видит у себя «в
этот день у тебя уже есть мероприятие» и сам решает, говорить или нет.

Гонорар: указывать необязательно. Инициатор видит суммы каждого,
участники друг друга — нет.

Опасное место по правам: «участник видит документ, но не видит одно поле»
в Firestore не выражается — суммы придётся разносить в подколлекцию.

## Часть 10. Напоминание по молчанию

Не общались неделю → за два дня «9 августа, подтвердите». Общались на
днях → ничего, не мешаем.

Люди из одной группы видятся каждый день, им напоминание — раздражение.

## Часть 11. Голос везде, где нужно объяснение

Записать голосом причину ухода, детали мероприятия, что угодно.

Отличие от WhatsApp: там голосовое теряется в переписке, здесь привязано
к конкретному дню и договорённости.

Техника написана — запись, волна, дакинг. Живёт только в чате, надо
вынести и привязать к мероприятию. Потребует нового пути в
`storage.rules`.

## Часть 12. История договора

Кто когда согласился, отпустил, промолчал, отменил, правил. Не для
наказания — чтобы не было «я не знал» и «я тебе звонил».

Сейчас журнала нет: `lastActionBy`/`lastActionType` — одно последнее
действие, перезаписываемое. Раунды предложения переписывают те же ключи.

Потребует подколлекцию событий, а она задевает все правила с `hasOnly` —
любой лишний ключ даёт отказ по правам целиком.

## Часть 13. Договоры переезжают в календарь

Сегодня `isAgree` — граница между двумя экранами. Поле потерялось →
запись молча уехала. Так случилась N40.

Становится: всё в календаре, рядом в одном дне. У договора видна вторая
сторона и статус. Список договоров — фильтр, не отдельное место.

## Часть 14. Ответ прямо из уведомления

«Razıyam» / «Bacarmıram» в самом уведомлении, не заходя в приложение.
Пока не нажал — договорённости нет.

Сейчас: push → тап → чат → найти плашку → нажать → ждать → перебросило.
Пять-семь касаний.

Требует: категории и действия в push на сервере, нативный обработчик на
обеих платформах, серверную запись ответа, снятие дублей
`recipientAgreed`/`roundStep`.

## Часть 15. Виджет на экране телефона

Три ближайших дня: занят или свободен. Не открывая приложение.

Ради самого частого случая: звонят, спрашивают «свободен 9-го?» —
отвечаешь, не отрывая телефон от уха.

## Ограничение, которое надо знать

Push на iOS никогда не работал. Entitlement на месте, живых iOS-токенов
ноль, 673 неудачные отправки за 30 дней. Это не «доделать», а «включить и
впервые проверить». Нужен платный аккаунт Apple.

От этого зависят: часть 14 целиком, часть 15 на iOS, часть 7 и часть 10 в
проверке. Код пишется полностью и заработает при включении.

## Долг по сторожам — восемь соседок, заход отдельный

**Правило (I13): у сторожа, строящего вердикт разбором текста, стоит
соседка «нашлось хоть что-то», и она падает на нуле.** Иначе «плохого не
нашлось» и «разбор ничего не видит» — один и тот же зелёный вывод.

Замер 07.08: таких вердиктов **13**, соседка есть у **5** (три в
`registry_freshness_test`, одна в `source_invariants_test`, одна у разбора
`git log`). **Остаются восемь**, в порядке убывания цены:

| # | Где | Почему здесь |
|---|---|---|
| **1** | **`source_invariants_test`, «удаление участника идёт только через `chatAfterDeparture`» — ДВА сравнения счётчиков: `membersWrites == activeWrites` и `calls == membersWrites`** | **I9 в чистом виде: проверка не может провалиться.** Сломайся разбор — все три счёта станут нулями, `0 == 0 == 0` пройдёт, и сторож скажет «пути ухода сходятся», не посмотрев ни на один. Остальные вердикты хотя бы требуют, чтобы разбор что-то нашёл; эти два **довольны тем, что не нашли ничего**, и потому опаснее шести ниже |
| 2 | `guards_are_guards_test` — обход `.contains('имя')` по всем тестам | сторож над сторожами: сломайся его разбор, и без присмотра останутся ВСЕ текстовые сторожа разом |
| 3 | `no_mock_data_test` — обход `_fallback…` | вердикт «мок-данных нет» по форме и есть «пустой вывод — хорошая новость» (I14) |
| 4–8 | `source_invariants_test` — пять оставшихся: `_applyParticipantSelection`, две ветки выхода из чужого мероприятия, `replacedEventId`, «`imtina etdi` не осталось» | вердикты «плохого не нашлось»; чинятся тем же приёмом, но каждый требует, чтобы разбор хоть что-то видел |

**Лечение у двух первых разное.** Сравнению счётчиков соседка не поможет:
нужен нижний порог у каждого счёта по отдельности (`calls`, `membersWrites`,
`activeWrites` — каждый `greaterThan(0)`), иначе равенство останется
истинным на нулях. Остальным хватает одной строки «нашлось хоть что-то».

Не работа плана и номера не занимает: это долг по сторожам, делается
отдельным заходом целиком, чтобы не оставить половину.

Диагноз с цифрами → план на согласование → код → diff → сборка →
проверка руками на двух устройствах.

После починки искать тот же класс рядом. Сверять данные с экраном, даже
когда экран выглядит правильно.
