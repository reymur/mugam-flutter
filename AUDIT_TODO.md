B1–B33 / A1–A5) и по ходу работы над ним. Обновляется **после каждого
этапа**: статус здесь должен отражать реальное состояние репозитория и
прода, а не то, что помнится в текущей сессии.

Статусы: `открыт` · `в работе` · `закрыт` (с коммитом) · `отложен` (с
причиной и этапом)

## Этап 4 — пагинация и история ✅ закрыт (не проверен на устройстве)

| # | Кр. | Находка | Статус |
|---|---|---|---|
| N1 | 🟠 | **Всплывание сообщений после очистки чата.** `_clearedAt` стартует `null`, локальный стор отдаёт данные с диска раньше, чем приходит `clearedBy` из сети → кадр со всеми старыми сообщениями, затем схлопывание. Подтверждено на устройстве | закрыт — `37bdbe9` |
| B7 | 🟠 | `hasMoreOlder` считается по длине страницы после фильтрации — при удалённых сообщениях пагинация обрывается, история недоступна | закрыт — `37bdbe9` |
| B8 | 🟠 | `clearedAt`-фильтр применяется после пагинации: подгруженная страница может отфильтроваться целиком | закрыт — `37bdbe9` |

Отсечка теперь живёт в `LocalMessageStore` рядом с сообщениями, которые она
фильтрует (то же время жизни, та же чистка при выходе), и читается
синхронно до создания подписок — гонка «диск против сети» убрана как
таковая, а не ускорена. Введено третье состояние: «не чистили» пишется
явным значением, отсутствие записи означает только «не знаем» и достижимо
лишь для чата, ни разу не открытого этим аккаунтом на этом устройстве.
Если отсечку установить не удалось (офлайн, ошибка слушателя), экран
показывает «Söhbət yüklənmədi / Bağlantınızı yoxlayın» с кнопкой повтора —
непрофильтрованный список не рисуется ни при каком таймауте. Состояние
самозалечивается: живой слушатель остаётся подписан и снимает его сам.

### Найдено по ходу Этапа 4

| # | Кр. | Находка | Статус |
|---|---|---|---|
| N10 | 🟠 | Галерея вложений не применяла отсечку вообще — после «Çatı təmizlə» лента и полоса превью листали всю доочисточную медиа-историю | закрыт — `37bdbe9` |
| N12 | 🟡 | После «Çatı təmizlə» без выхода из чата первое отправленное сообщение «проезжало» снизу вверх: `_scrollToBottom` анимировал 300 мс из позиции, оставшейся от уже стёртой истории, а анимировать не по чему. Воспроизводилось каждый раз; при выходе-возврате не проявлялось только потому, что свежий экран идёт по ветке мгновенного прыжка | закрыт — подтверждён на устройстве |
| N11 | 🟠 | Квитанции о прочтении и сверка устаревшего превью читали видимый список. `lastReadMsgId` разрешает клиент собеседника, поэтому выбор более старого id (из-за «удалить у меня» на последнем входящем) навсегда оставил бы отправителю его сообщение непрочитанным — форма отказа L2 с другой стороны. Разделено через `rawMessages` | закрыт — `37bdbe9` |

**Проверено на устройстве 02.08:** открытие очищенного чата без кадра
всплывания (N1); первое сообщение после очистки — и при выходе-возврате, и
без выхода из чата (после N12).

**Осталось проверить:** прокрутка вглубь истории с удалёнными сообщениями
(B7); страница, целиком попадающая под отсечку (B8); галерея вложений после
очистки (N10); обычная переписка на регрессию квитанций (N11) — двусторонняя,
нужны оба устройства.

Состояние «Söhbət yüklənmədi» **через UI недостижимо** — проверено попыткой
02.08. `watchChats` запрашивает саму коллекцию `chats`, то есть те же
документы, на которых лежит отсечка, а офлайн-кэш Firestore включён (по
умолчанию, настройки не переопределены). Отсюда развилка без третьего
исхода: список не загрузился — до экрана чата не добраться вовсе (кнопка
«Mesaj» в профиле и пуш тоже требуют сети); список загрузился — документ
чата уже в кэше, и слушатель отсечки отвечает из него мгновенно даже
офлайн. Состояние остаётся достижимым только при ошибке слушателя (отказ в
правах) и в окне обновления у пользователей с локальной историей от старой
сборки. Это свойство конструкции, а не пробел в тестировании: непрофильтро-
ванный список не рисуется ни при каком исходе.

| B20 | 🟡 | Поднять upload timeout до 120 с для крупного видео на медленной сети | открыт |

| N3 | 🟠 | Перенос `mediaImageCount` на сервер **+ разовый пересчёт дрейфа**. Оба направления переноса дают двойной учёт или недосчёт, пока живы старые сборки — нужен пересчёт по фактическому числу изображений | открыт |

**Принцип для всех переносов клиент→сервер** (выведен при откате
`mediaImageCount`): переносить только операции, **идемпотентные по своей
природе** — пересчёт вместо инкремента, проверка существования перед
удалением вместо слепого delete. Тогда старая сборка, делающая то же
самое, не ломает результат, а безвредно дублирует. Флаги-маркеры версии в
схеме ради миграционного окна — хуже самой проблемы.
